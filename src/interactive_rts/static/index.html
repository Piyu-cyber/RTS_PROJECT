System Motivation

The Real-Time Vision Problem

Standard Vision Transformers (ViTs) are optimized for average classification accuracy on static image sets. However, when deployed in real-time cyber-physical systems (such as autonomous robotics, drone navigation, or industrial inspection), images arrive as continuous requests with strict deadlines.

The Fundamental Bottleneck:

When image arrival rate exceeds the GPU’s batch-1 inference throughput, request queues explode. Under standard First-In First-Out (FIFO) processing with fixed-capacity models, earlier requests monopolize the GPU, causing cascading delays that make subsequent requests miss their deadlines—even if the predictions are 100% correct.

📥
1. Dynamic Influx
Images arrive at unpredictable intervals ($r_i$) with application-specific relative deadlines ($D_i$).
⚙️
2. Finite GPU Compute
Single-lane GPU execution requires non-preemptive inference intervals ($C_k \approx 2.7\text{–}3.8\text{ ms}$).
⚡
3. Adaptive Pruning
EViT dynamically trims inattentive patch tokens (196 → 49 tokens) to save up to 1.07 ms of slack per frame.
Absolute Deadline $$d_i = r_i + D_i$$
•
Queue Waiting Time $$W_i = t_{\text{dispatch}} - r_i$$
•
Dispatch Slack $$s_i(M) = d_i - (t_{\text{dispatch}} + C_M)$$
•
Timing Success Criterion $$C_i \le d_i \iff s_i \ge 0$$

What This Experiment Does Not Prove (Scientific Limitations)

Rigorously documented in compliance with Phase 24B research audit standards.

1. Soft Real-Time vs. Hard WCET Guarantees

Our timing metrics rely on empirical $p95$ and median execution measurements. Due to OS thread scheduling, PCIe bus contention, and GPU driver overheads on Windows 11, these bounds do not constitute formal, provable Worst-Case Execution Time (WCET) guarantees required by safety-critical avionics or automotive systems.

2. Hardware & Batch Size Dependency

Sub-4ms latencies require batch size = 1 accelerated by CUDA Graphs on an NVIDIA GeForce RTX 4060 Laptop GPU. Under eager PyTorch execution without CUDA graphs, kernel launch overhead inflates execution to $13.4\text{–}15.7\text{ ms}$, exceeding typical tight deadlines ($5.0\text{ ms}$).

3. Empirical Driving Scene Accuracy

We evaluate empirical classification accuracy directly on held-out BDD100K driving scene test images ($C=6$), reporting 65.3%–71.1% top-1 accuracy under physical RTX 4060 GPU execution.

4. Non-Preemptive GPU Queueing Dynamics

Under non-preemptive GPU execution, EDF queue ordering alone provides no advantage over FIFO when deadlines are monotonic with arrival order (as seen in 8 out of 10 workloads). In unconstrained overload without admission control, EDF can even induce domino misses.

Formal RTS Conservation Accounting Proofs

$$N_{\text{adm}} + N_{\text{rej}} = N_{\text{off}}$$ Every offered request is either admitted into the system or rejected at the arrival inlet.
$$N_{\text{comp}} + N_{\text{exp}} = N_{\text{adm}}$$ Every admitted request either completes execution on the GPU or expires while waiting in queue.
$$N_{\text{ontime}} + N_{\text{late}} = N_{\text{comp}}$$ Every completed request is strictly partitioned into on-time or late completion.
